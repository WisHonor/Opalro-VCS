# Milestone 9 attack surface: conflicts (red-team session RT21, decision 024)

Milestone 9 is the third of v0.2. Until now a combine that met a conflict stopped. Now it goes through and **keeps** the conflict: the combined save holds, at each place that clashes, a small record naming the versions (yours, the one where the lines parted, theirs), and the folder shows either a text with marker lines or your version. The person fixes the places when they choose and records the fixes. It is the first milestone since the storage format was frozen that writes something new into a save, and the first where a save can hold a place whose contents are "not decided yet".

- **The conflict record** (`docs/storage-format.md` §8). A listing entry of kind 6 names a record: an odd number of versions (3 to 255; Opalro writes 3), each present or absent with a kind, an ID and a size, and optionally the conflict's **own version**: what the folder holds for it once the person has touched it, with a marker length when it is a marked text. At most 16 KiB. "What a conflict stands as" is its own version if it has one, else its first version; either may be absent.
- **The `conflicts` feature.** A project's `format` file lists it. New projects and imports have it; a project made by Opalro 0.1 gains it only through `opalro setup --upgrade`. Without it, everything behaves as 0.1 did: a conflict entry is an entry this version leaves alone, and a combine that would keep a conflict stops.
- **`opalro combine`** keeps conflicts and ends with 0. `--only-if-clean` promises that after it succeeds the save the line is on holds no conflict (made, carried from a line, or reached by a forward). What still stops any combine: both lines changed a place that one of them already holds in conflict, at or below it (never a conflict inside a conflict); a rules file (`opalro.toml`) that can't be read whole where it would decide a text file.
- **In the folder.** A text both lines changed is written with markers (`<`, `|`, `=`, `>` runs, longer than any line of the three versions that looks like one, the middle part always there, labels naming the lines and their saves). Anything else stands as your line's version, or as nothing if your line removed it. `status` lists each place and how it stands; `goto`, `discard`, the shelf, `undo` and `redo` write and protect a place as what it stands as.
- **`save`** carries conflicts along. A text with no marker lines left is fixed; one with markers left is saved as the conflict's own version and stays a conflict; a picture changed in place stays a conflict with the changed file as its own version; nothing in the folder decides a conflict without markers.
- **`opalro resolve`** records fixes: all the folder shows fixed, or the paths (or patterns) named; `--keep mine|theirs` takes one side whole at each place named; `--copy mine|theirs|before --to <file>` writes one version out to look at. It records into the combined save when that save may be replaced, else into a save of its own. One diary step that `undo` takes back.
- **Moves and starting points.** A file moved to two places, moved against a removal, or moved onto something else is kept as a conflict where the file went, never below another conflict's place. Where two lines have several common starting points that disagree, the start is "unknown" there: what both lines hold alike is kept, anything else is a whole conflict.
- **`show`, `changes --save`, Git's words.** Three new kinds of change (in conflict, still in conflict, conflict fixed); `merge --abort`, `merge --continue`, `checkout --ours`, `mergetool` and the rest are explained.

Threat list: `docs/security.md` §4 (T52 to T54 are this milestone's; T43, T46 and T47 were updated). The decisions: `docs/decisions/174-…` to `180-…`, and `181-…`, which collects what building refined: **read 181 and the rulings file first** (`docs/plans/2026-11-14-milestone-9-rulings.md`, its "While building" part): they list the places where this code was wrong while it was being built, each found by a review or by CI and fixed. Those are the best map of where it may still be wrong. `docs/terminal.md` says what each command prints, `docs/json.md` what programs read, `docs/storage-format.md` §8 what a record holds and what every reader refuses.

## Where the code is

- `crates/opal-vcs-core/src/conflict.rs`: the record, its decoder, `stands_as`, and the one table of what a save does at a place (`settled`); `conflict/standing.rs`: reading a save's listings as they stand (`Listings`); `conflict/markers.rs`: marker lines, read and written.
- `crates/opal-vcs-core/src/store.rs`: `Store::conflict` (refuses a record over 16 KiB before unpacking it) and `met_conflict` (remembers the records a command has read, within a budget).
- `crates/opal-vcs-core/src/repo.rs`, `setup.rs`: the feature and `setup --upgrade`.
- `crates/opal-vcs-core/src/status.rs`, `snapshot.rs`, `snapshot/walk.rs`, `snapshot/only.rs`: `status` and `save` with conflicts (the walk; a save of some paths; folders gone from disk).
- `crates/opal-vcs-core/src/writeout.rs`, `kept.rs`, `switch.rs`, `shelf.rs`, `undo.rs`: writing the folder.
- `crates/opal-vcs-core/src/combine.rs`, `combine/tree.rs`, `combine/text.rs`, `moves.rs`, `rules.rs`: the merge that keeps conflicts, the marked text, moves, the unknown start, both lines' rules.
- `crates/opal-vcs-core/src/resolve.rs`, `fsio.rs`: `resolve`, and the one write of a file outside the save machinery (`--copy`).
- `crates/opal-vcs-core/src/tidy.rs`, `verify.rs`, `listing.rs` (`SaveLimits::add_all_standing`): what is kept, what is checked, a save's limits.
- `crates/opal-vcs/src/main.rs`, `combine_output.rs`, `resolve_output.rs`, `show_output.rs`, `output.rs`, `git_words.rs`: the command line.

## Places worth attacking

1. **A version that is lost, or a conflict decided that nobody decided.** These are the two failures this milestone must never have.
   - A combine that goes through and leaves a version a line saved in no entry and no record: moves across both lines, chains of moves, a file moved onto a place the other line changed, moves into and out of folders that are themselves one side of a conflict, starting points that disagree (three or more of them, in every order of their IDs), a start that already holds a conflict.
   - A `save` that turns a conflict without markers into an ordinary file, or drops it: `save <paths>` naming a place, a path below it, its folder, or a pattern; folders deleted from disk; a file put where a conflict stands as nothing; renames and names that differ only in letter case; `save --amend`; a place this computer can't hold.
   - A `resolve` that records something the person did not settle: a file changed between its two reads of the folder (it waits for an answer in between); a file whose markers come and go; `--keep` without paths through any route; a pattern that matches more than the person meant; the question about markers left answered for them.
2. **Planted records.** Everything in a record is untrusted. Every refusal `docs/storage-format.md` §8 lists; versions that lie about kind or size; a folder version as large and as deep as a save; a link version leading out of the project or into `.opalro`; a version whose folder holds a spelling of `.opalro` or `.git`; a record of 5 or 255 versions; a record just over 16 KiB that would unpack to much more; a conflict inside the folder another conflict stands as (planted: Opalro never makes one); the same record named from thousands of places; a record whose own version is a marked text with a marker length that doesn't match the text. Against each of: `status`, `goto`, `discard`, the shelf, `undo`, `redo`, `save`, `combine`, `resolve --keep`, `resolve --copy`, `tidy`, `verify`.
3. **Memory and time with many conflicts.** *A known lead, not yet settled:* the store remembers records only within a budget, but each command also keeps a map of its own of the records it has read (`status`, the save walk, a save of some paths, the combine's made records), with no limit. A record Opalro makes holds three versions; a planted one can hold 255. A save may hold 10,000,000 entries. Measure what `status`, `save` and `goto` hold for a planted save of very many conflict entries each naming a different record of 255 versions, against the same save with ordinary entries. Also: a folder version met at very many places (the check for a conflict below it); `status` on thousands of marked files (it reads each on every run); a marked text at 64 MiB; twelve 30 MiB texts conflicted at once.
4. **Marked texts at the edges.** Runs of 255 and 256 marker characters starting a line; a file whose lines already look like marker lines of the chosen length after one edit; CRLF on one side and LF on the other; no last line break; an empty side; the two sides differing only in line endings; a clash at the first or last line; labels from hostile line and tag names (escape sequences, right-to-left overrides, 500 bytes); a name of exactly the length that fills the label. Does the reader (`markers::scan`) find exactly the places the writer made, and does taking one part everywhere give that side byte for byte?
5. **The promise that a project without conflicts pays nothing.** `status`, `save` and `goto` on a wide project (100,000 files) with the feature and no conflict, against the same project without the feature: the listings and records read, and the time. And with a few conflicts deep in the tree.
6. **`--only-if-clean`.** Find a way for it to end with 0 on a save that holds a conflict: a conflict carried inside a folder only one line changed; a forward; a forward onto a save past a save's limits; a combine whose only conflicts are held by both lines alike; a project without the feature; the nothing-to-combine case on a line that already holds conflicts (it changes nothing: is what it says true?).
7. **`resolve --copy` and `resolve --keep` against the folder and the disk.** `--to` destinations: an existing file, a link, a dangling link, `.opalro` under any spelling the drive takes for it, through `..`, through a link or junction in the path, through a second name for the same folder, a device name; a destination folder that changes between the check and the write. `--keep` where the folder holds a half-finished fix (the safety copy), a file open in another program, a link, a folder where a file goes, a name this computer can't hold, a folder version taking the save past a save's limits.
8. **Undo, redo, crash, tidy.** `undo` and `redo` across a kept combine, a `save` that kept a conflict, a `resolve` with and without `--keep`; a crash at every write of each (the next command finishes the step or it never happened; the safety copy stays); `tidy` inside and past the undo window: is any version a kept conflict names ever freed, through a line, a tag, a shelf, a safety copy, or the "from" side of a diary step?
9. **The feature and old versions.** `opalro setup --upgrade` stopped halfway, run twice, run by two commands at once, declined; the `format` file with features in odd order, repeated, or unknown; a project made by 0.1 with planted kind-6 entries and records (nothing must change there: `status`, `goto`, `save`, `combine`, `tidy`, `verify` as 0.1); a project upgraded here and then opened by 0.1 (it must refuse cleanly); two commands at once, one that keeps conflicts and one that does not.
10. **What a person is shown.** Rows of places in conflict in `status`, `combine`, `resolve`, `show` (hostile paths, at most 100, then a count); marker labels; the default message `Fixed conflicts in <path>`; hints and `Next:` lines (nothing from the project inside a command a person might copy); `--json` documents against `docs/json.md`.
11. **Git's words.** `merge`, `merge --abort`, `merge --continue`, `checkout --ours <file>`, `checkout --theirs <file>`, `restore --ours`, `mergetool`, `add`: forms that run something other than what the person meant, or put what they typed into a command.
12. **What the two sessions on milestone 8 did not reach** (`docs/plans/2026-11-01-milestone-1-follow-ups.md`, the rows headed "Milestone 9's red team"): two commands at once (`combine` racing `save`, `goto`, `undo`, `tidy`, another `combine`, and now `resolve`); a reshuffle past the bound on following moves; a comparison that runs out of its two seconds; text files at the size and line limits; a rules file changed on both lines; true notes moving 100,000 files back and forth over many saves; a `tidy` by 0.1 past its window after a line was deleted; and a planted `opalro.toml` whose rules all say `true` with a path some 2,000 folders deep changed on both lines.
