# Milestone 10 attack surface: `who`, the amend check, two speed changes (red-team session RT23, decision 024)

Milestone 10 is the last of v0.2. It adds one command that only reads, makes one check exact, and takes out work two commands did twice. Nothing new is written into a save: the storage format did not change. That makes this session different from milestone 9's: the first thing to prove is that a command which says it changes nothing changes nothing, and that it never names the wrong save.

- **`opalro who <file> [--save <save>] [--json]`**, and Git's words `blame` and `annotate`, which run it ([decision 184](../docs/decisions/184-opalro-who-the-save-behind-each-line.md), with a "Correction" at its end). Beside every line of a file it names the save the line is from: the file as it is in the folder (lines in no save yet are marked not saved yet) or, with `--save`, as a save has it.
  - **How a line finds its save.** Each save's version is compared, line by line, with the version each parent has, the first parent first; a line a parent has goes on to that parent's side; a line no parent has is that save's. Lines are compared without their line endings. A combine's own lines are the combine's.
  - **Moves** are followed only where a save's move notes say the file came from another path **and the note is true** of the save and its first parent (`moves::true_of`). History imported from Git has no notes.
  - **A place in conflict** is read as what stands there (`Listings::standing`): the marked text, your version, or nothing.
  - **Limits.** A version over 64 MiB, of more than 1,000,000 lines, or with a zero byte in its first 8,000 bytes takes no lines: the trail ends there. Each comparison has a deadline of 2 seconds (`OPALRO_DIFF_DEADLINE_MS` in builds with `fault-injection`); past it the answer is "coarse" and says so.
  - **Cost.** A version is read only when a parent holds other contents. Versions wait in a heap ordered by the saver's time, which a planted save can set to anything; lines that reach a version after its turn are answered from what was remembered: at most 256 comparisons and 2^20 stretches of lines, the oldest dropped first (`REMEMBERED`, `REMEMBERED_STRETCHES` in `who.rs`). There is no limit on how far back it reads.
  - **It changes nothing.** It opens the project as `verify` does (`Repository::discover_untouched`: leftovers in `.opalro/tmp` stay, the lock file is not touched), and its handle is told to store no caches (`store_no_caches`; the three cache writers ask `storing_key`). One thing is made and removed: the file the drive's name test uses under `.opalro/tmp`, as for every command given a path.
  - **What it prints.** One row per line: the save's short ID, the author's name (cut at 20 characters on a terminal only), the day, the line's number, the line; rows that repeat the one above are dim. Everything from the project is escaped. `--json` gives runs and the saves named, raw.
- **The check before `opalro save --amend`** ([decision 185](../docs/decisions/185-save-amend-and-a-save-something-else-holds.md), with its "Correction"). An amend is refused when another line, a tag or a server line names the save or has it in its history **through any parent** (`ancestry::holder`). To make the usual case fast, a small sealed cache, `cache/last-made` (`lastmade.rs`; magic `OPALMADE`; at most 65,536 notes, one for each line's newest save), says "Opalro made this save in this diary step, and nothing has moved since": then nothing is asked. `opalro resolve` uses the same rule to decide whether a fix replaces the combined save or becomes a save of its own. `cache/other-lines`, which 0.1 wrote, is no longer read or written.
- **Reading one file from the folder** (`changes::in_folder`) and finding a typed path's stored spelling (`writeout::Tree::entry_as_typed`). A name the system cannot hold is "no file there".
- **A write-out limited to some paths makes a folder only when it was named or something is written into it** (`writeout.rs`, `made_on_the_way`): a fault from milestone 9 that the model test found (`opalro resolve --keep` made a deleted folder again).
- **Two speed changes that must alter no write, no flush and no check** ([decision 186](../docs/decisions/186-speed-before-v0.2.md)):
  - the folder walk fetches a folder's last-saved listing once per folder, looks each name up once, and checks an entry's kind before it consults the conflict records (`snapshot.rs` `Last::before`; `conflict/standing.rs` `as_it_stands`);
  - `goto` and `combine` no longer load the file cache a second time for the switch: the read of the folder hands on **the bytes it stored** and the switch decodes them (`FileCache::store_giving_body`, `load_or_stored`; `switch.rs`, `writeout.rs` `apply_with`). The file cache's answers are part of how a switch decides that a file holds nothing unsaved before it overwrites it.
- **The package** ([decision 187](../docs/decisions/187-v0.2s-package.md)): the version becomes 0.2.0; nothing is tagged or published.

## Places worth attacking

Most valuable first.

1. **`who` changes something.** Three reviews in a row each found one more path on which it wrote (the cache of change IDs through the shortening of IDs; the same cache through the lookup of `--save <ID>`; the leftovers in `.opalro/tmp` through the way it opened). Find the fourth. Every form of the command (`who`, `blame`, `annotate`; text and `--json`; `--save` by line, `line@server`, tag, change ID, fingerprint, a word that is ambiguous, a word that is nothing), every refusal, from a folder below the top, in a project with stale caches, caches with a bad seal, leftovers under every temp name, a stopped switch's journal, an unfinished start or import inside it, kept conflicts, no user key. Compare everything under `.opalro` and the folder before and after, also files that appear and vanish again while it runs (the probe is the one that is allowed). What does it do in a project it cannot write (read-only `.opalro`): the page says it cannot run there; does it fail cleanly?
2. **A line named for a save that never held it,** or a line with no answer. Planted histories against the walk: saves whose times lie (a parent dated after its child; all equal; far future; negative), 1,024 parents, the same version reached by many ways after its turn; a history planted so that more than 256 comparisons must be remembered, and then one more; move notes that look true and are not (the file at `from` differs by one byte; `from` is a folder; `from` equals `to`; a ring of notes a→b, b→a; a note whose path fails validation; 100,000 notes on one save); a conflict record at the path, in a project that keeps conflicts and in one that does not; a listing that lies about a file's size (a known open point: what a comparison found is remembered by the two versions' contents but not by the sizes a listing claims, so a lying listing can make the trail stop early or not by which comparison came first: show whether that can name a save that does not hold the line, not only another right one); versions exactly at the limits and one past; a file whose last line has no ending; `\r` alone; a version that is not text between two that are. Coarse answers: set the deadline to 0 and see whether a coarse comparison ever names a save that does not hold the line.
3. **`who` made to hang, crash or eat memory.** The sandbox has 4 GB. A file of 1,000,000 short lines through thousands of saves; histories built so that comparisons multiply; what the memory of comparisons really holds at its bounds (a review reasoned 100 to 160 MiB, unconfirmed); a line of 64 MiB; a path of every odd kind. Nothing may recurse on the history's depth.
4. **What a person is shown.** A line of the file, an author's name, a path or a save's message with escape sequences, carriage returns, backspaces, bidi controls, wide characters, a name of 10,000 characters: can a row be made to look like another row, like the footer about unsaved lines, like an `error:` or `hint:` line; can a hint be made to carry text from the project inside a command to paste? `--json` must stay one valid document whatever the bytes.
5. **An amend allowed while something holds the save.** The note that lets the check be skipped is sealed with the user's own key, which a copied or planted project does not have: can a note still be made to vouch for a save it should not (a note for a line that then moved by `undo`, `redo`, `goto`, a rename of the line, a forward, a combine; two commands at once; a crash between the save and the note; a full list of 65,536 notes; a note file with a good seal copied from another project of the same user)? Can another line, a tag or a server line come to hold the save between the check and the amend? A holder that names a missing save stops the check: can that be used to block every amend in a project (a denial, said as damage)? `resolve` decides by the same rule whether it replaces the combined save: can it be made to replace a save another line holds, so that the other line names a save that is gone?
6. **A switch that trusts what it should not.** The switch now decodes bytes handed on by the scan in the same command. Unsaved work must survive a `goto` or `combine` in every state of `cache/files`: missing, stale, a bad seal, a good seal over a body that does not decode, truncated, a body from another project of the same user, a cache that says a changed file is unchanged (it is sealed with the user's key: what can an attacker who can write `.opalro` but lacks the key do?), a file changed between the scan and the switch. Compare with the build before the change if you can (`git` is not in the copy; say what you would have compared).
7. **The walk's hoisted lookups.** An entry that is not a conflict but carries a conflict record's ID; a folder that was a file in the last save; a name in another letter case (platform tests); a listing that cannot be read: is any entry now decided differently from milestone 9's code, or an error lost? (A test pins the first of these since this milestone.)
8. **What milestone 9's two sessions left** ([decision 183](../docs/decisions/183-red-team-m9-session-2-rulings.md)): `combine` and `resolve` run at the same time; a conflict below a folder the other line moved; three common starting points in every order of their IDs.
9. **The package:** any place that names the wrong version, or a page that promises what the program does not do (`docs/releases/v0.2.0.md` against the program).

## Known and not settled (do not report these as findings; prove them worse or put them to rest)

- `who` cannot run on a project that cannot be written at all (the drive's name test makes a file).
- The memory of comparisons is bounded by count, not by bytes.
- A read of the folder keeps the file cache's bytes alive until the command ends.
- Once, on a loaded Windows machine, a test failed taking the change lock with a file error whose text was not kept. If you can make a lock call fail (not wait) with nothing holding the lock, that is a finding.
- In history imported from Git `who` follows no rename; where a combine took the other line's version of a file whole, `who` asks the first parent first and `git blame` does not (both ruled; see decision 184's Correction).
