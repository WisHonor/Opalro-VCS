RT25 timings, 2026-11-18, in the no-network sandbox (4 CPUs, 4 GB), one import at a time.
"read" is the import's rchar from /proc, last seen before it ended.

Repositories (scripts in this folder):
  chain   mkchain.sh <dir> 2000 <commits> pack|loose|packs: a file 2000 folders deep whose
          contents flip in every commit, so each comparison reads two chains of one-entry trees.
  padded  padpack.py <dir> <commits> 4000000 none|stored|fixed: two one-file top trees, each
          stored whole with 4 MB of empty deflate blocks before its 29 bytes; the commits flip
          between them. The pack is 8 MB whatever the number of commits.

Debug build of milestone 11 (141ebaf):
  chain, one pack:        2 commits 0.73 s, 50 commits 10.14 s, 200 commits 39.28 s
  chain, 50 commits:      loose 13.68 s; loose beside 4,095 packs 75.04 s
  padded, 50 commits:     none 0.14 s; stored 8.52 s; fixed stopped by hand after 754 s,
                          having read 37.5 MB in 742 s of CPU time
  RT25-1's proof:         failed after 48.7 s, the import having read 2,305 MiB of a 64 MiB
                          repository

Git 2.39 on the padded fixed repository: `git cat-file -p` of both top trees 0.032 s,
`git fsck` 0.074 s.

So in release, with fixed-block padding, milestone 11 adds about 12 s for each commit
(8 MB of trees inflated, 58 bytes counted against the 1 GiB allowance): 1,000 commits would
take about 3.3 hours and 10,000 about 33, where v0.2 takes 30 s for any number.
