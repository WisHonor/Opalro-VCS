# Milestone 11 ("Loose ends"): rulings made while the owner was away

On 2026-11-17 the owner wrote: "continue working on the opalro and continue whats missing, features, issues or whatever it is. Im gonna be away so work autonomously". Milestone 11 is the first of v0.3 ([decision 193](../decisions/193-the-next-version-starts-with-what-v0.2-left.md)): the six things the owner's review of v0.2 put first in the next version ([decision 189](../decisions/189-the-owners-review-of-v0.2.md) point 5). This file lists what was decided without the owner, so that each item can be confirmed or reversed. Nothing here is merged into `main`, which stays v0.2 until the owner publishes it.

The decisions are records [193](../decisions/193-the-next-version-starts-with-what-v0.2-left.md) to [197](../decisions/197-red-team-m11-rulings.md). The plan is [2026-11-17-milestone-11-loose-ends.md](2026-11-17-milestone-11-loose-ends.md).

## Please confirm

The first four carry a real choice; the rest keep what the owner already asked for, in the way set out.

1. **An import now gives different fingerprints than 0.2 did** ([195](../decisions/195-the-import-records-the-renames-it-is-sure-of.md)). A rename noted in a save is part of the save's fingerprint, so every save from the first commit that renames a file without changing it gets a new one; the change IDs people see stay. Each version imports the same repository the same way every time; projects already imported keep their saves. The other choice was a separate list of renames beside the saves, a second place for one fact and a new thing on disk after format 1 freezes.
2. **It doesn't follow Git's own `README.md`.** The example that started this (23 of 75 lines where `who` and `git blame` disagree) is a rename with 7 lines changed in the same commit, so it isn't the same contents and isn't noted. Only guessing by likeness would follow it, and that stays deferred.
3. **`opalro status` now lists empty folders** ([196](../decisions/196-empty-folders-in-a-switch-and-in-status.md)), added and removed, as rows of their own (`empty folder` where a file's size goes), and `--json` gains `empty_folders`. A folder that holds only ignored files shows as an added empty folder, because that is what a save records. The other choices: show only saved empty folders that are gone, or say nothing and let `save` keep acting silently.
4. **An import whose comparison of commits would cost more than its allowance stops, committing nothing** ([195](../decisions/195-the-import-records-the-renames-it-is-sure-of.md), [197](../decisions/197-red-team-m11-rulings.md)). To note renames, the import compares each commit with its first parent, and may spend on that at most the larger of 1 GiB of work and 32 times what converting the Git trees cost. Git's own history uses about a sixteenth of it, and a history built to make importing slow stops within seconds. An honest history that goes back and forth between the same big folders more than about 30 times would stop too, where 0.2 imported it without notes; the stop can come late in a long import, and a second run stops the same way. The other choices: keep importing and note no more moves from there on, which is unsafe, since where that falls depends on how Git packed the repository, so two clones would get different fingerprints; or two budgets, one counted only in what the trees hold, the same for every clone, past which the import notes no more moves, and the one that counts what reading costs, past which it stops. That is more rule, worth it only if such honest histories turn up.
5. **Short names** ([194](../decisions/194-a-change-ids-start-counts-from-four-letters.md)): text counts as a change ID's start from 4 letters, and 1 to 3 letters of k to z that name nothing get a hint saying so (for Jujutsu's habit of typing the one or two letters it highlights).
6. **A switch makes no folder that only conflicts standing as nothing fill, and `resolve --keep` takes out a folder it empties that is gone from disk** (196), as `resolve` and a save of some paths already do. Folders saved empty, and folders that hold only project links or names this computer can't write, are made as before.
7. **The program says "Opalro before 0.2"** where it said "Opalro 0.1" ([193](../decisions/193-the-next-version-starts-with-what-v0.2-left.md) point 2).
8. **The flush after the journal is removed is only tested, not changed** (193 point 1). What the tests show, and a recommendation, are in the follow-ups' "For the owner to decide".
9. **Git's rule for `who` at a combine is only measured,** on a throwaway branch (193 point 1); the numbers are in benchmarks.md.
10. **The work lives on `v0.3`** (193 point 3), made from `main`; `main` stays v0.2 untouched until it is published, and the version stays 0.2.0 on `v0.3` until v0.3 is packaged.

## Every ruling, as made

Each ruling below was made while the milestone was built, and its evidence is in the plan's ledger. Those with a real choice come first; each says what it would cost if it were wrong.

### Rulings with a real choice

1. **The comparison's allowance counts what reading a tree costs, and a cache keeps the trees it reads** (the red team's RT25-1, [decision 197](../decisions/197-red-team-m11-rulings.md)). The import may spend comparing at most the larger of 1 GiB and 32 times what converting its Git trees cost: their bytes and 1 KiB for each read, never their compressed bytes. A tree compared again costs its bytes, from a cache of 64 MiB by its count (the least recently used dropped first); a tree read again also costs 1 KiB, 1 KiB for each pack index searched, and 1,000 for each compressed byte its stream takes past what zlib needs. Why: the first count, in what trees hold, let a padded repository keep an import busy for hours; compressed bytes vary a thousandfold in time, so they must never buy allowance. If wrong: a crafted repository still costs up to 32 times what converting it cost, plus the floor (but see 6).
2. **The import stops, rather than stopping to note moves, past that allowance.** Item 4 above, for the owner to confirm.
3. **The base counts no pack index searches** (RT26-1, decision 197). The fix wave first counted 1 KiB for each, since the converter pays them; the second red-team session showed a search takes tens of nanoseconds, so 4,095 filler packs bought a history the floor stops in seconds about 36 minutes of comparing. Searches are now charged only where a tree is read again, so the base doesn't depend on how Git packed the repository. If wrong: an honest repository of very many packs (Git merges them at 50) pays its misses' searches without buying them; on Git's own history that is 3,662 KiB against an allowance of about 83 GiB.
4. **The comparison walks depth first, one folder for each level** (RT26-2, decision 197), as the converter's own walk does, so it holds no whole path for each folder waiting. It hands the pairing of moves the same paths as before, in another order, which the pairing doesn't depend on. If wrong: a wide folder deep down costs memory in proportion to its width, as converting it does.
5. **No third red-team session** after the second session's fixes (decision 197), as in milestones 7, 8 and 9: one fix is a line, the other changes how the walk keeps its folders, not what it compares; each has its proof, and the scoped re-review read both. If wrong: a change to the comparison's walk is on `v0.3` unattacked until milestone 12's session, which gets it in its brief.
6. **One estimated hole is left open: fixed-Huffman blocks that each carry a short match** (decision 197). They cost Opalro's inflater about 2 µs a block, like empty ones, but take no more compressed bytes than they give, so a tree written that way and read again is charged as plain bytes. The scoped re-review estimated that a million one-file trees could buy about two hours of comparing, where v0.2 imports the same repository in about a minute and a half; nobody built it. Closing it means counting deflate blocks in the Git reader, or an inflater that keeps the fixed tables (decision 031 chose one that forbids `unsafe`). Its cost is a constant factor of the repository's size, the kind T7 accepts for rebuilding through deltas, not a tiny repository that costs hours. So it is written in security.md T59 as a known limit, is on the follow-ups list, and goes first to milestone 12's red team. If wrong: a crafted repository of about a million small objects can keep an import busy for about two hours; it can be stopped, and nothing is written.
7. **An import trades memory for time.** The cache that makes the comparison cheap costs about 150 MB more peak memory than v0.2 on Git's own history, bounded by the cache's size whatever the repository; the import takes 11 to 13 % longer than 0.2's where it took 35 to 40 % longer (benchmarks.md §16). A leaner cache is on the follow-ups. If wrong: imports use that much more memory until it is built.
8. **A rename beside an unmoved file with the same contents is noted** (Task 6). The plan's first wording ("no note") was a slip: decision 195 adopts the save's rule (decision 168), where a twin left in place neither left nor arrived, and Git prints `R100` for it. If wrong: a true note is kept that a stricter rule would drop; no wrong note can come of it.
9. **An empty folder that takes the place of a file, or a file that takes the place of a saved empty folder, gets its own empty-folder row in `status`** beside the file's row (Task 4). Decision 196 shows empty folders added and removed, and `status` must account for every folder a save records. If wrong: one row in a rare case.
10. **`resolve --keep` asks the disk whether a folder is gone, and only "not found", "not a folder" or a link standing in its place counts as gone** (Task 3 and the fix wave). A folder that is there but can't be opened is kept. If wrong: a folder that can't be opened would have been left out of the save.
11. **A folder a scoped switch names (`opalro discard d`) is not made when only conflicts standing as nothing fill it** (Task 3). Decision 196 point 1 says so of every switch. If wrong: one clause makes a named folder always.
12. **A switch counts an entry it removes to put one of another kind in its place,** a file giving way to a folder and a folder to a file or link, in its words and in `--json`'s `removed` (RT25-2). A file and a link trading places stays one write, which `written` shows. If wrong: a count in one rare case.
13. **The comparison's stop has words of its own** (the final review's M-2). It says this is a limit of the import's rename notes, not damage in the repository, offers only to delete the folder it kept, and prints the allowance in whole GiB rounded up. If wrong: the number overstates the allowance by less than 1 GiB; one line prints a decimal.
14. **The slow inflater (the first session's S1) is counted where the comparison reads a tree again; in the converter's one read of each object it stays as in 0.2,** bounded by the repository's size, and is on the follow-ups. If wrong: a padded repository takes as long to convert as 0.2 took.
15. **Git's rule for `who` at a combine: the numbers stand as "Git's rule as built"** (Task 8). The throwaway build may differ from `git blame` for a file renamed on the first parent's side; the follow-ups row says so. If wrong: a few of the 49 lines are counted under the wrong rule; the conclusion (a small difference, a little faster) stands.

### Rulings that keep what was decided, or only fix words

16. **The plan's global constraint** "no flush, write or check changes" now allows the changes decisions 195 and 196 make (before Task 1). The decisions were always binding.
17. **`moves::moves_by` takes any error type,** with no bound its body doesn't need (Task 5).
18. **Tests check the program's words,** `Switched to line …`, where a task's brief misquoted them (Task 1).

21. **Undo or redo across a step that removed an empty folder only conflicts fill was not a gap:** the case went to the red team, which ran it and found `status` right every time (Task 3).
22. **Small review findings were fixed in one round each** (Tasks 1 and 2), then gathered into one fix wave after the whole-branch review: 23 fixed there, 6 put on the follow-ups' "Should do" list.
23. **`changes` says "No file changed since …"** where only an empty folder changed, as `changes --save` already did (M-1).
24. **Removed empty folders get a test pass of their own** in the model; random histories rarely delete a folder saved empty, so the main pass can't require it (fix wave).
25. **The check that Opalro follows Git's merges reads the store's move notes,** not the refusal's words, which say "changed on both lines" for a moved file both lines edited (fix wave).
26. **Two small findings of the last review were fixed in a short third round:** the cache's feed no longer copies a tree too big for it, and a test's doc comment went back to its function.
27. **The order of work after the build:** the whole-branch review; one fix wave; a second red-team session on what it changed; a second round for that session's two findings; the scoped re-review of both rounds; decision 197 for both sessions (as decision 188 did for milestone 10); then these pages. The import's time on Git's own history was measured again on the last code.
